## 0. 전략의 출발점

**LESSON:ON**이 증명한 것: "레슨권"이라는 기능 하나를 전면에 내세우면, PT·요가·필라테스·골프·무술이라는
서로 다른 업종이 **하나의 카피** 아래 묶인다. 범용 스케줄러가 아니라, 자신의 문제를 해결하는 전용 앱처럼 느껴진다.

이 논리를 전체 8개 업종 대분류로 확장한다. 각 앱은 **하나의 앵커 기능**(가장 차별화된 기능)을 전면에 걸고,
나머지 공통 기능(스케줄·역할·자동배정·알림)은 백그라운드에서 지원한다.

**하지 않을 것:** 코드 포크, 별도 DB, 업종 하드코딩 if 분기.
모든 차이는 `feature_flags`, `tenant_mode`, 브랜드 설정 데이터로만 표현한다.

> Phase 2 = 소규모 추가 개발 필요 (1~4주)
> Phase 3 = 전용 기능 개발 필요 (1~2개월)

## 4. 앱별 상세 전략

### 4-1. LESSON:ON — 레슨·스포츠 특화

**태그라인:** "강사 혼자 다 챙기던 회원권 관리, 이제 문자 한 통이 대신합니다"

**타겟:** PT 트레이너·요가·필라테스·골프·무술 강사 (1인 사업자 ~ 소규모 스튜디오)

**앵커 기능 (현재 구현됨):**
- 레슨권 패키지 등록 (횟수·유효기간 설정)
- 회원별 레슨권 소진 현황 추적
- 만료 임박 자동 감지 → SMS 일괄/개별 발송

**지원 기능 (현재 구현됨):**
- 강사별 회원 개별 스케줄 (`회원개별` 모드)
- 역할별 색상 구분 (indicator_bar)
- AI 자연어 예약: "박지은님 이번주 화요일 10시 요가 예약"
- 커스텀 필드: 보유 레슨권 종류·부상 이력·목표

**feature_flags 프리셋:**
```json
{ "lesson_packages": true, "autoassign": true, "notifications": true }
```

**온보딩 딥링크:** `?vertical=lesson-sports`

**출시 우선순위:** ★★★ Phase 1 — 추가 개발 없이 즉시 출시 가능

### 4-2. CLASS:ON — 교육·학원 특화

**태그라인:** "수강권 소진부터 출석까지, 학원 원장님의 잔업을 줄여드립니다"

**타겟:** 학원·교습소·과외 강사·튜터 (학교는 보조 타겟)

**앵커 기능 (현재 구현됨 — 레슨권 재레이블링):**
- 수강권 패키지 (레슨권 동일 기능, 라벨만 "수강권"으로 표기)
- 수강권 만료 임박 학부모 SMS 발송
- 강사별 반 편성 스케줄

**추가 개발 필요 (🔧 4주 이내):**
- **출석 체크** — 스케줄 셀에 "출석 확인" 버튼 추가, 출석률 요약 뷰
- 커스텀 필드 기본 프리셋: 학교·학년·수강 과목·학부모 연락처

**feature_flags 프리셋:**
```json
{ "lesson_packages": true, "autoassign": true, "attendance": true }
```

**온보딩 딥링크:** `?vertical=education-academy`

**출시 우선순위:** ★★☆ Phase 2 — 출석 체크 기능 개발 후 출시

### 4-3. SHIFT:ON — 외식·유통 교대 근무 특화

**태그라인:** "알바 스케줄 짜는 데 30분? 이제 5분이면 됩니다"

**타겟:** 식당·카페·편의점·마트 사장님 (알바·파트타임 관리)

**앵커 기능 (현재 구현됨):**
- 자동 배정 — 역할별 인원 비율에 맞게 스케줄 자동 생성
- D-1 배정 알림 — 내일 출근 직원에게 자동 알림
- 역할 배정 (홀·주방·카운터 등 역할 색상 구분)
- AI 자연어 배정: "이번 주 토요일 오후 홀 2명 추가 배정"

**추가 개발 필요 (🔧 2주):**
- **근무 시간 집계** — 월별 직원별 총 근무 시간 요약 뷰
- 커스텀 필드 기본 프리셋: 시급·고용 형태·은행 계좌

**future (🚀):**
- 급여 계산 연동 (시급 × 근무 시간 자동 계산)

**feature_flags 프리셋:**
```json
{ "lesson_packages": false, "autoassign": true, "notifications": true }
```

**온보딩 딥링크:** `?vertical=food-retail`

**출시 우선순위:** ★★★ Phase 1 — 자동배정+알림으로 즉시 출시 가능

### 4-4. SALON:ON — 뷰티·예약 특화

**태그라인:** "고객이 직접 시술사를 고르고 예약합니다. 전화 없이"

**앵커 기능 (현재 구현됨):**
- 비회원 모드 — 고객(비회원) 이름·연락처를 슬롯에 직접 입력
- 시간별 스케줄 뷰 — 스타일리스트별 시간대 예약 현황
- 커스텀 필드: 시술 종류·요청 사항·알러지 이력

**추가 개발 필요 (🚀 4~8주):**
- **고객용 온라인 예약 링크** — 조직별 퍼블릭 예약 페이지(스타일리스트 선택 → 시간대 선택 → 이름·연락처 입력)

### 4-5. CARE:ON — 의료·돌봄 교대 배정 특화

**태그라인:** "의료진 교대표, 빠짐 없이 채워지고 담당자는 하루 전 받습니다"

**타겟:** 병원·의원·치과·요양원·어린이집 (의료진·간병인·교사 교대 관리)

**앵커 기능 (현재 구현됨):**
- 역할별 자동 배정 (의사·간호사·간병인·교사 등)
- D-1 배정 알림 (내일 근무자에게 자동 알림)
- 요양원/병원 특화 커스텀 필드 프리셋 (전문 자격증·담당 병동 등)

**추가 개발 필요 (🔧🚀 4~8주):**
- **출석/근무 확인 체크** (실제 출근 여부 기록)

- 주야간 교대 지원 (24시간 연속 배정 시 시각적 구분)

**feature_flags 프리셋:**
```json
{ "lesson_packages": false, "autoassign": true, "notifications": true, "care_mapping": true }
```

### 4-6. SERVE:ON — 봉사·공공 프로그램 배정 특화

**태그라인:** "봉사자 모집부터 배정·확인까지, 엑셀 없이 한 화면에"

**타겟:** 복지시설·자원봉사단체·종교단체·도서관·시민단체

**앵커 기능 (현재 구현됨):**
- 비회원/회원공유 혼합 운영 — 봉사자(비회원 1회성)와 고정 스태프(회원) 동시 관리
- 프로그램별 시간표 슬롯 구성
- 역할 배정 (봉사자·담당자·프로그램 운영자 구분)
- 커스텀 필드: 봉사 가능 요일·자격·차량 여부

**추가 개발 필요 (🚀 4주):**
- **봉사 시간 집계 뷰** — 봉사자별 누적 시간 요약
- **봉사 확인서 자동 생성** — PDF 다운로드 (봉사자명·기간·시간 자동 기입)

**feature_flags 프리셋:**
```json
{ "lesson_packages": false, "autoassign": true, "volunteer_hours": true }
```

**온보딩 딥링크:** `?vertical=public-welfare`

**출시 우선순위:** ★★★ Phase 1 — 봉사 시간 집계 없이도 배정·관리 기능만으로 즉시 출시 가능

### 4-7. WORK:ON — 전문·사무 팀 스케줄 특화

**태그라인:** "팀 업무 스케줄, 구글 캘린더와 함께 한 곳에서"

**타겟:** IT·법무·회계·디자인·부동산·행정기관 (팀 규모 5~50명)

**앵커 기능 (현재 구현됨):**
- 팀원별 업무 배정 스케줄 (회원공유 모드)
- 자동 배정 (프로젝트별 담당자 자동 할당)
- AI 자연어 배정: "이번주 개발팀 미팅 화요일 오후 3시 전체"
- 커스텀 필드: 프로젝트명·클라이언트·우선순위

**추가 개발 필요 (🚀 4~8주):**
- **Google Calendar 양방향 연동** (로드맵 항목) — DTS 배정이 구글 캘린더에 자동 반영
- **근무 시간 집계** — 프로젝트별·팀원별 투입 시간 요약

**feature_flags 프리셋:**
```json
{ "lesson_packages": false, "autoassign": true, "calendar_sync": true }
```

**온보딩 딥링크:** `?vertical=professional-office`

**출시 우선순위:** ★★☆ Phase 2 — Google Calendar 연동이 핵심 차별점, 연동 전에도 팀 스케줄러로 출시 가능

## 5. 공통 기술 선행 작업 (모든 앱 출시 전 1회만 구현)

모든 버티컬 앱이 공유하는 기반 작업. **이 4가지가 완료되면 Phase 1 앱 3개를 동시에 출시할 수 있다.**

### 5-1. `feature_flags` 스키마 추가

```sql
-- supabase/migrations/084_feature_flags.sql
ALTER TABLE tenants
  ALTER COLUMN settings SET DEFAULT '{}'::jsonb;

-- 기존 settings jsonb 안에 feature_flags 키 추가 (마이그레이션 불필요, 코드에서 기본값 처리)
-- 예: settings->'feature_flags'->>'lesson_packages' IS NULL → true (하위 호환)
```

`AdminPage.tsx`의 `adminIsFreeform` 패턴을 확장:

```ts
const ff = adminTenant?.settings?.feature_flags ?? {}
const showLessons    = ff.lesson_packages !== false   // 기본 true (기존 조직 호환)
const showAutoassign = !adminIsFreeform && ff.autoassign !== false
```

### 5-2. 버티컬 프리셋 맵 (`src/lib/verticalPresets.ts`)

```ts
export const VERTICAL_PRESETS: Record<string, VerticalPreset> = {
  'lesson-sports': {
    tenant_mode:    '회원개별',
    feature_flags:  { lesson_packages: true, autoassign: true },
    default_roles:  ['강사', '회원'],
    custom_fields:  [/* 보유 레슨권, 부상 이력 */],
  },
  'education-academy': { /* ... */ },
  'food-retail':       { /* ... */ },
  'beauty-salon':      { /* ... */ },
  'medical-care':      { /* ... */ },
  'public-welfare':    { /* ... */ },
  'professional-office':{ /* ... */ },
}
```

셋업 위자드 진입 시 `?vertical=lesson-sports` 파라미터를 읽어 프리셋 자동 적용.
`wizardModeRecommendation.ts`의 패턴을 "업종 → 전체 프리셋"으로 확장.

### 5-3. 브랜드 설정 레이어 (`src/lib/brandConfig.ts`)

```ts
// 빌드 타임 환경 변수로 주입
export const BRAND = {
  name:     import.meta.env.VITE_BRAND_NAME ?? 'Dynamic Team Schedule',
  tagline:  import.meta.env.VITE_BRAND_TAGLINE ?? '다중 조직 스케줄 관리',
  color:    import.meta.env.VITE_BRAND_COLOR ?? '#E05A3A',
  vertical: import.meta.env.VITE_VERTICAL ?? 'generic',
}
```

PWA `manifest.webmanifest`의 `name`, `short_name`, `theme_color`도 이 값에서 파생.
각 버티컬은 `.env.lesson-on`, `.env.shift-on` 등 별도 환경 변수 파일로 관리.

### 5-4. 슈퍼관리자 콘솔에 버티컬 필터 추가

`OrgDrawer.tsx`에 조직별 `feature_flags` 토글 UI 추가.
시스템관리자가 특정 조직의 기능을 수동 오버라이드할 수 있는 안전망.

## 6. 단계별 출시 로드맵

```
Phase 1 (즉시 ~ 4주): 기반 작업 + 첫 3개 앱 출시
  ├─ 공통 기반: feature_flags 스키마, 버티컬 프리셋 맵, 브랜드 설정 레이어
  ├─ LESSON:ON 랜딩페이지 + 온보딩 딥링크
  ├─ SHIFT:ON 랜딩페이지 + 온보딩 딥링크
  └─ SERVE:ON 랜딩페이지 + 온보딩 딥링크

Phase 2 (4~8주): 소규모 개발 + 2개 앱 추가
  ├─ 출석 체크 기능 개발 → CLASS:ON 출시
  ├─ 근무 시간 집계 기능 → SHIFT:ON 기능 업그레이드
  ├─ Google Calendar 연동 착수 → WORK:ON 출시 (연동 없이 선 출시)
  └─ SALON:ON 고객용 예약 링크 개발 착수

Phase 3 (8~16주): 전용 기능 개발 + 나머지 앱
  ├─ SALON:ON 고객용 예약 링크 완성 → 정식 출시
  ├─ CARE:ON 담당자-케어 대상 매핑 → 출시
  ├─ SERVE:ON 봉사 확인서 발급 → 기능 업그레이드
  └─ Google Calendar 연동 완성 → WORK:ON 기능 업그레이드

Phase 4 (지속): 검증 지표 보고 피벗 또는 확장
  └─ 전환율/활성화율 낮은 버티컬 → 카피 수정 or 기능 피벗
```
